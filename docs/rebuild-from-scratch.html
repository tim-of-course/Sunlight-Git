1. Verdict

Do not iterate the current core

The UI is the asset. The runtime is the liability. Elixir/Phoenix/LiveState is a capable server stack, but this product is a local desktop Git tool. The BEAM plus a browser tab plus a Rust tray is three runtimes for one window. A single per-repository mutex then forbids the most common workflow: leave bun run dev up and still stage, commit, and push.

Rebuild from scratch as a Tauri 2 + Rust + SolidJS 1.x app. Port assets/src/styles.css and the column/sidebar/drawer layout almost 1:1. Replace LiveState, the Workspace GenServer bottleneck, SolidJS 2.0 beta, and the Git-vs-command lock. Keep the Git CLI, the parsers, the port-conflict helper, and the local-only trust model.

Keep

  • Dark column workspace and visual language
  • Commit graph, recents, persisted order
  • Git porcelain via the installed git
  • Vite port-conflict / Replace Port behavior
  • Loopback-only, trusted-local-tool model

Replace

  • Phoenix, Bandit, LiveState, OTP supervisors
  • SolidJS 2.0.0-beta.0 and next-channel Vite plugins
  • One-mailbox Workspace + per-repo exclusive lock
  • Full-state JSON patches for terminal output
  • Browser-tab host and separate tray process

3. Current architecture

Sunlight is a local-only multi-repo Git GUI. Production is an Elixir release on 127.0.0.1:4200, started at login by a Rust tray. Development uses Phoenix on :4201 with Vite build --watch. The browser is the real UI host.

1. TrayRust sunlight-tray + winit. Starts/stops the release.
2. BEAMPhoenix Endpoint, PubSub, Workspace GenServer, per-repo GenServers.
3. LiveStateOne websocket. JSONDiff patches of the entire workspace.
4. Solid 2 betaOne 1.8k-line App.tsx. File editor is a drawer.
5. Git CLIMany git subprocesses per snapshot. Auth via installed Git.

Runtime topology

Scheduled Task / LaunchAgent
  └─ sunlight-tray.exe          (always on)
       └─ mix release / beam    (Phoenix + Bandit, loopback)
            ├─ Workspace        (ONE GenServer for all repos)
            ├─ Repository * N   (Git + terminal + snapshot)
            └─ WorkspaceChannel (LiveState, JSONDiff)
Browser tab ──WebSocket──► /socket topic "workspace"

Why this felt reasonable

  • OTP isolation and restart look like a good fit for N repositories.
  • LiveState promised a tiny frontend: server owns state, client renders.
  • Solid is a low-RAM UI library compared with React.
  • Git CLI preserves credential manager, hooks, and SSH agent behavior.

Those ideas are sound. The implementation couples them into a single mailbox and a single exclusive lock, then ships a beta UI runtime on top. The isolation never reaches the user-facing workflows.

4. Core defects

Ranked by how much they hurt stability, concurrency, or footprint. These are the reasons a rebuild beats continued patching.

P0

Repository-wide exclusive lock

A running command sets terminal.running. Any Git perform then returns "Stop the running command before changing repository state". The inverse is also true: a Git op blocks starting a command. The UI folds both into one busy() flag and disables Commit, Push, Stage, Fetch, and close.

lib/sunlight/repository.ex · assets/src/App.tsx RepositoryColumn

P0

Workspace GenServer is a global queue

Every add/remove/reorder/perform/diff/list_files/read_file/search/open/write goes through Sunlight.Workspace via GenServer.call. File reads and diffs hibernate that process. Opening a file in repo A can stall Git UI in repo B. Snapshot-on-join walks every repository serially.

lib/sunlight/workspace.ex handle_call/3

P0

Terminal output is broadcast as workspace state

Each stdout chunk updates a 32 KiB rolling string, PubSub-notifies every socket, re-snapshots the repo, then JSONDiffs the entire workspace (all columns, commits, branches, file lists, plus the terminal buffer). A noisy Vite server becomes a CPU fan. This is the opposite of a low-footprint local tool.

repository.ex handle_info({port, {:data, _}}) · workspace_channel.ex update_state/2

P1

SolidJS 2.0 beta is load-bearing

Production UI depends on solid-js@2.0.0-beta.0, @solidjs/web beta, vite-plugin-solid@3.0.0-next.0, and onSettled / two-argument createEffect. HMR is disabled. phx-live-state is not a Solid 2 product. Beta churn is a stability tax with no user-facing benefit.

assets/package.json · assets/src/liveState.ts · assets/vite.config.ts

P1

File watcher cannot work in the release

repository_file_watcher defaults to false, so repos poll every 30s. Even if enabled, file_system is declared runtime: false in mix.exs, so the production release does not include it. Status in the UI is stale by design.

mix.exs deps · config/config.exs · repository.ex maybe_start_watcher/1

P1

Git snapshot is a subprocess storm

A full snapshot runs status (porcelain v2), up to three rev-parse --git-path probes for merge/rebase, for-each-ref, remote, stash list, and log --all (25 commits). Periodic refresh still pays for status. Large repos + many columns = constant Git CPU even when idle.

lib/sunlight/git.ex snapshot/1 and status/1

P1

Three processes, none of them a real window

Tray, BEAM, and a Chrome/Edge tab. No native folder picker, no OS file associations inside the app, no WebView2 sharing. Opening Sunlight means opening a browser profile the README already warns must be trusted. This is both a UX and a RAM problem.

native/sunlight-tray · README.md · page_controller.ex

P2

LiveState version wrap and giant UI module

Channel versions are rem(n + 1, 1001). A long session can collide. App.tsx is ~1850 lines with sidebar, columns, graph, file tree, editor, and terminal in one file. That is a maintenance hazard, not a visual one.

workspace_channel.ex update_state/2 · assets/src/App.tsx

P2

Editor is one file per repository, in a modal

openFiles is keyed by repository id. Opening a second file in the same repo replaces the first. The drawer covers the workspace. There is no quick-open, no tabs, no open-from-status-list, no Cursor/VS Code target, and a raw textarea with a 1 MiB cap.

5. Git + dev server concurrency

This is the product bug

A developer’s normal loop is: start the dev server, edit, commit, push, keep the server running. Sunlight currently makes that illegal. The lock is not required by Git. It is an artifact of one GenServer owning both the Port and the Git task.

What actually conflicts

LeftRightConflict?Rebuild rule
Long-running command (Vite, mix, tests) status / diff / log / read file No Always concurrent
Long-running command stage / unstage / commit / fetch / pull / push Rare (index.lock) Concurrent. Retry index.lock with backoff. Surface Git’s error if still locked.
Long-running command checkout / merge / rebase / reset / clean Yes, worktree Allow, but confirm. Do not disable the button behind a global busy flag.
Mutating Git A Mutating Git A Yes Serialize mutating Git only per repo. Queue, do not reject.
Repo A anything Repo B anything No Fully isolated. Never one global mailbox.
Command stdout UI rendering Only if mis-designed Append-only events. Never patch the whole workspace.

Target lock policy

per repository:
  git_write_queue   // stage, commit, push, fetch, branch, stash, …
  git_read_pool     // status, diff, log, ls-files, grep  (N concurrent, cap 2)
  command_session   // 0..1 long-running process group (Job Object / process group)
  file_io           // read/write editor files; never waits on git_write_queue

close repository:
  allowed while command runs IF user confirms stop-or-detach
  mutating git drains the write queue first

Windows: put the command in a Job Object so Stop kills the tree (today’s taskkill /T /F is the right idea). Unix: start a new process group and signal the group. Do not hold a GenServer/actor mailbox while waiting on Git.

6. File-open UX

Opening files is the other workflow that feels unfinished. The visual file tree is fine. The interaction model is not.

Today

  • Add repo by pasting a path. No folder picker.
  • Files tab calls git ls-files -co, sends the full list, builds a tree on the client.
  • Click file → request_file through Workspace + Repository, then a modal drawer.
  • One open file per repo. Opening another replaces it.
  • “Open” on the row uses OS default (cmd start / open / xdg-open).
  • Content search is git grep --no-index on the Repository process.
  • Status-list files only open a diff, not the file.
  • Symlinks refused. Binary/non-UTF-8 refused. 1 MiB cap.

Rebuild

  • Native “Add repository” folder dialog. Keep paste + recents.
  • Quick open (Ctrl/Cmd+P) over the active column.
  • Click a changed file: diff stays default; a second action opens the file.
  • Editor tabs per repo (or a persistent pane), not a single keyed slot.
  • “Open outside” targets Cursor, then VS Code, then OS default. Remember the choice.
  • Virtualized tree. Do not ship 50k paths over IPC until filtered.
  • File reads bypass the Git write queue.
  • Watch the open file for external edits; prompt on dirty conflict.
  • Keep the path jail, UTF-8 check, and size cap. Raise cap only for view-only.
Drawer vs pane

Keep the existing drawer chrome if it still feels like Sunlight. Change the behavior: tabs inside the drawer, keyboard open, and do not block Git buttons while a file is open. Visual continuity matters more than whether the editor is a right drawer or a split.

7. RAM and CPU

The current release already tries to be small: rel/vm.args.eex pins +S 2:2, one dirty CPU scheduler, one IO scheduler, and disables scheduler busy-wait. That is the right instinct applied to the wrong VM.

ProcessIdle today (order of magnitude)Notes
Rust tray 10–25 MiB winit event loop for a menu icon.
BEAM release 40–100 MiB Even with tiny schedulers. Grows with N repo snapshots in RAM.
Browser tab 80–200 MiB Usually the largest cost. Separate Chromium/Edge process.
Polling Git CPU spikes every 30s × N 6–9 processes per full snapshot. Worse if the watcher were on.
Dev-server logs CPU + GC while running JSONDiff of workspace on every Port data message.

Typical always-on cost: 130–300 MiB plus Git. Target always-on cost with a few repos idle: under 80 MiB RSS for the Sunlight process on Windows (WebView2 shared with Edge), tray in-process, no BEAM, no extra browser tab. User-started dev servers do not count against Sunlight.

CPU rules for the rebuild

  • No periodic Git if a recursive watcher is healthy. Poll only as fallback (60s+).
  • Debounce watcher events (250ms is fine). Ignore node_modules, .git/objects, build dirs.
  • Incremental status: run git status first; fetch history/refs only when HEAD, upstream, or ref files change.
  • Terminal: binary/text stream with client-side ring buffer. Server does not retain 32 KiB in workspace state.
  • Do not clone full repo snapshots to every listener. Push typed events.

8. Recommended stack

Primary recommendation

Tauri 2 + Rust 2024 + SolidJS 1.9 + the existing CSS. One Windows/macOS process. WebView2 / WKWebView. Native dialogs. Tray plugin. IPC instead of Phoenix sockets. Git still invoked as the system git.

OptionIdle RAMFits this product?Decision
Tauri 2 + Rust + Solid 1.9 Lowest practical Native window, dialogs, tray, process control, keep CSS UI Choose
Rust axum daemon + browser tab Tiny daemon, fat tab Keeps the current host model; still no folder picker Reject
Wails / Go Similar, GC Fine, but Rust already exists in-tree for the tray Backup
Electron Worst Native UX, terrible footprint Reject
Keep Elixir, fix locks Still a BEAM + tab Can fix concurrency, cannot hit min RAM Reject for rebuild goal
Iced / egui / Slint Excellent Throws away the UI you like Reject
Solid 2 beta / Svelte 5 / Preact Similar JS Solid 1.9 is stable and closest to current JSX Solid 1.9 only

Why not Elixir

Elixir is excellent at many concurrent sockets. This app has one user, one machine, a handful of repos, and a lot of OS processes. The BEAM’s strengths (soft real-time, huge connection counts, hot upgrade) are unused. Its costs (VM, release, schedulers, extra language for Windows process/Job Object/WebView work) are paid every hour the tray is running. The tray is already Rust. Put the core there.

Why not Solid 2

Solid 1.9 is production. The current code already fights 2.0 APIs (onSettled, two-arg effects, next Vite plugin, HMR off). Rebuild on 1.9. Revisit 2.0 only after it is stable and the core is boring.

Why keep the Git binary

git2 / libgit2 is tempting for RAM, but it does not speak Git Credential Manager, SSH agent, or hooks the same way. Sunlight’s README correctly delegates auth to the installed client. Spawn git with GIT_TERMINAL_PROMPT=0 as today. Cap concurrent Git processes. Parse porcelain in Rust (port the existing parsers).

10. Event model

LiveState’s “one document, patch it” model is wrong for terminals and file trees. Use commands (UI → core) and events (core → UI). The UI holds view state.

Commands (examples)

workspace.add { path } | workspace.add_pick_folder
workspace.remove { id }
workspace.reorder { ids }
repo.refresh { id }
repo.git { id, op, payload }          // stage, commit, push, …
repo.command.run { id, line }
repo.command.stop { id }
repo.command.replace_port { id }
files.tree { id, prefix? }
files.search { id, query }
files.open { id, path }
files.save { id, path, content }
files.open_outside { id, path, target? }  // cursor | vscode | os
diff.request { id, path, staged }

Events (examples)

workspace.snapshot          // rare: connect / persist
repo.summary { id, status, head, ahead, behind, busy_git? }
repo.refs { id, branches, remotes, stashes }
repo.history { id, commits }
repo.git.progress { id, op, phase }
repo.git.done { id, op, notice?, error? }
cmd.started { id, line, pid }
cmd.chunk { id, bytes }     // UI appends to a ring buffer
cmd.exited { id, code, port_conflict? }
files.tree_page { id, paths, done }
files.content { id, path, content, mtime }
files.changed_on_disk { id, path, mtime }

On connect, send a compact workspace snapshot (ids, names, paths, last summaries). Do not send every file path or the terminal buffer until that column needs it.

11. Rebuild plan

New repository or apps/sunlight-next in this repo is fine. Do not try to strangler-fig Phoenix into Tauri. Port tests and CSS. Cut over when parity is real.

  1. Scaffold. Tauri 2 app, Solid 1.9, port styles.css, empty columns, tray, loopback-free (no HTTP server). Persist workspace JSON in the same LocalAppData paths so users do not lose recents.
  2. Git read path. Port status/ref/commit parsers with the existing ExUnit fixtures translated to Rust tests. One repo column showing status + history.
  3. Git write queue. Stage, commit, push, fetch, branch, stash, merge continue/abort. Queue mutating ops. Never a global busy that disables the terminal.
  4. Command session. Run/stop, Job Object, port conflict + Replace Port, append-only chunks. Prove: bun run dev up, then commit and push in the same column.
  5. Watcher. Debounced, filtered. Incremental snapshot. Poll fallback.
  6. Files. Native add-folder, quick open, tree virtualization, editor tabs, open-outside to Cursor, dirty-file watch.
  7. Parity pass. Diff drawer, graph, publish/upstream, undo last commit (keep current revert-not-reset semantics), discard confirmations.
  8. Install. One signed exe, Start Menu, login item. Retire Mix release, Install-Sunlight.ps1 BEAM staging, and the extra tray supervisor unless still needed as a tiny watchdog.
Parity traps

Undo last commit is a git revert, not reset --soft. Commit with nothing staged does add -A then commit. Windows argv cannot contain raw tabs in for-each-ref --format (the Elixir code uses %09 on purpose). Port those behaviors; do not “simplify” them.

12. Acceptance criteria

The rebuild is done when all of the following are true.

  • MUST look like Sunlight: same column workspace, colors, graph, Commands/Changes/History/Files.
  • MUST allow commit and push while a command is running in that repository.
  • MUST allow a command to start while a fetch/push is in flight (queue Git writes; do not reject the command).
  • MUST isolate repositories: work in A never waits on B.
  • MUST open a folder with a native dialog, and still accept a pasted path.
  • MUST open more than one file per repo without discarding the previous buffer unless the user closes it.
  • MUST keep Git authentication on the installed Git client.
  • MUST stay local-only; no bind on 0.0.0.0.
  • MUST use SolidJS 1.x (or later stable), not 2.0 beta.
  • SHOULD idle under ~80 MiB RSS on Windows with 3 small repos and no command running.
  • SHOULD use a file watcher, not 30s polling, as the primary refresh.
  • SHOULD stream command output without copying the full workspace over IPC.
  • SHOULD offer Open in Cursor / VS Code / OS.
  • MAY add a real PTY later. v1 can stay “one command line + stdout”.
  • MAY keep the Mix app around as a reference until cutover, then archive it.
